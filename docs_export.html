프로젝트 개요

Project Overview

서비스 소개

gudocs-fe는 사용자가 여러 구독 서비스(OTT, 음악 스트리밍, 클라우드 스토리지 등)를 하나의 인터페이스에서 통합 관리할 수 있는 구독 관리 대시보드의 프론트엔드입니다.

핵심 기능 목표
  • 구독 서비스 통합 관리
  • 월별 지출 현황 시각화
  • 결제 예정일 알림
  • 카테고리별 분석
개발 환경
  • Node.js (ESM 모듈)
  • 개발 서버: localhost:5173
  • 백엔드 API: localhost:8080
  • 패키지 매니저: npm

npm 스크립트

명령어역할
npm run devVite 개발 서버 시작 (HMR 포함, localhost:5173)
npm run buildTypeScript 타입 검사 후 Vite 프로덕션 빌드
npm run lintESLint 코드 정적 분석 실행
npm run preview프로덕션 빌드 결과물 로컬 미리보기

상태 관리 (Zustand)

Global State Management with Zustand 5

이 프로젝트는 Zustand를 사용해 전역 상태를 관리합니다. Redux보다 훨씬 적은 보일러플레이트로 동일한 기능을 구현할 수 있는 경량 상태 관리 라이브러리입니다.

useAuthStore — 인증 상태

// src/stores/useAuthStore.ts
import { create } from "zustand";
import type { User } from "../type/auth";

interface AuthStore {
  user: User | null;          // 로그인된 사용자 정보 (없으면 null)
  isAuthenticated: boolean;   // 로그인 여부 플래그
  setUser: (user: User) => void;  // 로그인 성공 시 호출
  logout: () => void;             // 로그아웃 시 호출
}

export const useAuthStore = create<AuthStore>((set) => ({
  user: null,
  isAuthenticated: false,
  setUser: (user) => set({ user, isAuthenticated: true }),
  logout: () => set({ user: null, isAuthenticated: false }),
}));

스토어 구조

항목타입설명
userUser | null현재 로그인된 사용자 객체 (id, email, name)
isAuthenticatedboolean인증 여부 — PrivateRoute에서 사용
setUser(user)Actionuser 저장 + isAuthenticated = true 설정
logout()Actionuser = null + isAuthenticated = false 초기화

컴포넌트에서 사용하는 방법

// 전체 스토어 구독
const { user, isAuthenticated, setUser, logout } = useAuthStore();

// 특정 값만 구독 (성능 최적화 — 불필요한 리렌더링 방지)
const isAuthenticated = useAuthStore((state) => state.isAuthenticated);
const user = useAuthStore((state) => state.user);
Zustand vs Redux: Zustand는 Provider 래핑 없이 바로 사용 가능하고, 보일러플레이트가 거의 없습니다. 현재 프로젝트처럼 인증 상태 등 단순한 전역 상태에 적합합니다.

API 레이어

HTTP Communication with Axios

axios 인스턴스 설정

// src/api/instance.ts
import axios from "axios";

export const server_axiosInstance = axios.create({
  baseURL: "http://localhost:8080", // Spring Boot 백엔드 서버
  timeout: 200000,                  // 200초 타임아웃
  withCredentials: true,            // 쿠키(세션) 자동 포함
});
설정 설명
  • baseURL: Spring Boot 백엔드 주소
  • timeout: 200초 (파일 업로드 등 대비)
  • withCredentials: HttpOnly 쿠키 기반 세션 인증
인증 방식
  • 쿠키 기반 세션 인증
  • 로그인 시 서버가 Set-Cookie 응답
  • 이후 요청에 자동으로 쿠키 전송
  • CORS 설정 필요 (백엔드)

인증 API 함수

// src/api/auth.ts
// 회원가입
export async function signUp(data: SignUpRequest): Promise<ApiResponse<SignUpResponseData>> {
  const response = await server_axiosInstance.post("/api/auth/signup", data);
  return response.data;
}

// 로그인
export async function login(data: LoginRequest) {
  const response = await server_axiosInstance.post("/api/auth/login", data);
  return response.data;
}

// 로그아웃
export async function logout() {
  const response = await server_axiosInstance.post("/api/auth/logout");
  return response.data;
}

// 현재 사용자 정보 조회 (세션 유지 확인)
export async function getUser(): Promise<ApiResponse<User>> {
  const response = await server_axiosInstance.get("/api/auth/me");
  return response.data;
}

TypeScript 타입 정의

Type Definitions & Interfaces

공통 API 응답 타입 (src/type/api.ts)

// src/type/api.ts
export interface ApiResponse<T> {
  message: string;   // 서버 응답 메시지
  success: boolean;  // 성공 여부
  data: T;           // 제네릭 — 실제 응답 데이터
}
제네릭 활용: ApiResponse<T>를 사용하면 모든 API의 응답 구조가 통일되면서도, 각 API마다 다른 데이터 타입을 타입 안전하게 사용할 수 있습니다. 예: ApiResponse<User>, ApiResponse<SignUpResponseData>

인증 관련 타입 (src/type/auth.ts)

// src/type/auth.ts

// 사용자 기본 정보
export interface User {
  id: number;
  email: string;
  name: string;
}

// 회원가입 요청 (User에서 id 제외 + 비밀번호 필드 추가)
export interface SignUpRequest extends Omit<User, "id"> {
  password: string;
  passwordConfirm: string;
}

// 회원가입 응답 데이터
export interface SignUpResponseData extends Omit<User, "password"> {
  name: string;
}

// 로그인 요청 (email + password만)
export interface LoginRequest extends Omit<User, "id" | "name"> {
  password: string;
}

타입 상속 구조

타입베이스필드
User—id, email, name
SignUpRequestUser (id 제외)email, name, password, passwordConfirm
SignUpResponseDataUserid, email, name
LoginRequestUser (id, name 제외)email, password
TypeScript Strict Mode 활성화: tsconfig.app.json에서 strict 옵션이 모두 켜져 있어 any 타입 사용 금지, 미사용 변수 오류, nullish 체크 등을 컴파일 타임에 강제합니다.

커스텀 훅 (Custom Hooks)

Business Logic Abstraction via React Hooks

이 프로젝트는 비즈니스 로직을 컴포넌트에서 분리하기 위해 커스텀 훅 패턴을 사용합니다. 컴포넌트는 UI 렌더링만 담당하고, 로직은 훅에서 처리합니다.

useAuth — 인증 로직 훅 (src/hooks/useAuth.ts)

함수/값타입설명
validateEmail(email: string) → boolean이메일 형식 정규식 검증
validatePassword(password: string) → boolean비밀번호 최소 8자 검증
validatePasswordMatch(pw, confirm) → boolean비밀번호 일치 여부 검증
handleLogin({ email, password }) → Promise로그인 API 호출 → 스토어 업데이트 → 대시보드 이동
handleRegister(SignUpRequest) → Promise회원가입 API 호출 → 성공 토스트 → 로그인 이동
handleLogout() → void로그아웃 API 호출 → 스토어 초기화 → 로그인 이동
 
// 사용 예 (LoginPage.tsx)
const { handleLogin, validateEmail, validatePassword } = useAuth();

const onSubmit = async (e: FormEvent) => {
  e.preventDefault();
  if (!validateEmail(email)) { setEmailError("올바른 이메일 형식이 아닙니다."); return; }
  if (!validatePassword(password)) { setPasswordError("8자 이상 입력해주세요."); return; }
  await handleLogin({ email, password });
};
훅 분리의 장점: 같은 유효성 검사 로직을 LoginPage와 RegisterPage 양쪽에서 재사용합니다. 컴포넌트 파일이 UI 로직만 담아 가독성이 높아집니다.

// 앱 시작 시 자동으로 실행되는 인증 상태 복구 로직
useEffect(() => {
  const fetchUser = async () => {
    try {
      const { data } = await getUser();  // GET /api/auth/me
      setUser(data);                     // 세션 유효 → 스토어에 유저 저장
    } catch {
      logout();                          // 세션 만료 → 인증 상태 초기화
    }
  };
  fetchUser();
}, []);
